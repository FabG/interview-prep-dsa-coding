# Problem queue and revision tracker

This is an original 50-problem starter selection for the [study plan](STUDY-PLAN.md), not a complete copy of any commercial curriculum. Start with five new problems per week, and reduce that number whenever reviews need more time.

Entries start as **N (not started)** and are updated as attempts are recorded. Problem links go to LeetCode. If access changes, choose a free alternative on the same topic rather than buying a subscription solely to complete a row.

Problem references use `week.position`: for example, `1.1` is the first problem in week one and `2.3` is the third problem in week two. Keep assigned IDs stable when recording notes and reviews.

The **Complexity** column records LeetCode difficulty (Easy, Medium or Hard), not runtime complexity. Labels were checked against each linked problem on October 25, 2026. Adaptive slots remain TBD until a problem is selected.

## Recording outcomes

- `N`: not started.
- `G`: solved with a hint, explanation, AI assistance or viewed code.
- `I`: solved independently during this attempt.
- `R`: successfully re-solved independently on a later date.

Use ISO dates (`YYYY-MM-DD`) for attempts. Set **To review again?** to **Yes** when another review is needed and **No** otherwise. Unattempted problems default to **No** until an attempt identifies a review need. Retain attempt history and any optional review dates in the problem note. A failed review takes priority over adding another new problem.

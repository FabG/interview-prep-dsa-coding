# Interview preparation workspace

Use `~/interview-prep-dsa-coding` as the authoritative location for this coding and DSA interview preparation project, including all future files.

Keep reference documents at the repository root, reusable note templates under `templates/`, and future material under `problems/`, `patterns/`, `weekly/` and `mocks/` as appropriate. Read README.md and STUDY-PLAN.md before changing the study plan. Preserve source links and research dates. Do not mark problems completed without evidence from the user. Commit or push only when requested.

The user prefers Python. Use Python by default for future solutions, code examples, exercises and language-specific study notes unless the user requests otherwise.

For every future coding problem, use `problems/week<week>/<week>-<position>-<leetcode-id>-<slug>/`. Match the week and position to the stable tracker reference and pad the LeetCode ID to at least four digits. For example, problem 1.1 lives in `problems/week1/1-1-0001-two-sum/`, and problem 1.2 lives in `problems/week1/1-2-0217-contains-duplicate/`. Include `problem-description.md`, `my-solution.py`, and `agent-solution.md`. Keep tracker links, relative links back to the root tracker, and local run commands consistent with this layout.

System design material lives under `system-design/`, with its own README, sources and tracker. Use stable IDs `SD-001` and folders `system-design/exercises/sd-001-<slug>/`. Store `problem-description.md`, `my-solution.md`, and `agent-solution.md` per exercise. Record theme and repository-assigned difficulty explicitly; preserve source attribution and distinguish external guidance from local authored answers.
